1. Yönetici Özeti (Executive Summary)

Bu rapor, DailyFlow üretkenlik ve finans takip uygulamasının Web (dailyflowweb.com) ve Android mobil platformları için gerçekleştirilen statik kod güvenliği analizi (SAST), veri akışı doğrulaması ve Playwright destekli çoklu tarayıcı çalışma zamanı testlerinin bulgularını sunar.

Denetim sonucunda uygulamanın "Local-First / Offline-First" mimarisi sayesinde merkezi sunucu ve veritabanı taşımadığı; bu sebeple çok kullanıcılı yetkilendirme açıkları (IDOR, oturum sızıntıları, API yetki aşımları) gibi geleneksel tehditleri mimari olarak barındırmadığı teyit edilmiştir. İstemci tarafında DOM tabanlı XSS korumalarının çalıştığı Playwright testleriyle kanıtlanmıştır. Buna karşın, Android Release Keystore imza anahtarları ve parolalarının kaynak kontrolü (Git) geçmişinde yer alması acil müdahale gerektiren en kritik bulgu olarak tespit edilmiştir.

4. SAST Kod Güvenliği ve Doğrulama Bulguları

Bulgu 1: Android İmza Anahtarlarının (.jks) Git Geçmişinde Bulunması ve Parolaların Açıkça Tanımlanması
KRİTİK / DOĞRULANDI

CWE Sınıflandırması: CWE-798 (Use of Hard-coded Credentials), CWE-200 (Exposure of Sensitive Information)

Etkilenen Dosyalar: android/app/build.gradle, android/app/dailyflow-release.jks, android/app/dailyflow-release-key.jks, .gitignore

Tespit Kanıtı:

// android/app/build.gradle (Satır 19-26) signingConfigs { release { storeFile file('dailyflow-release.jks') storePassword '[GİZLENDİ / REDACTED_PASSWORD]' keyAlias 'dailyflow' keyPassword '[GİZLENDİ / REDACTED_PASSWORD]' } }

git log --all -p -- "*jks" sorgulamasında anahtar dosyalarının geçmiş commit'lerde (5413219... ve 597cf62...) Git geçmişine eklendiği doğrulanmıştır. Kök .gitignore dosyasında *.jks engellenmemiş, android/.gitignore dosyasında ise kural yorum satırı olarak kalmıştır.

Olası Etki: Depoya erişebilen herhangi bir saldırgan, Google Play'e yüklenen uygulamanın imza sertifikasını ve parolasını elde ederek kötü niyetli sahte güncelleme paketleri oluşturabilir.

Önerilen Düzeltme: Keystore parolaları key.properties veya CI/CD Secrets ortamına taşınmalı; .gitignore içine *.jks eklenmeli; Git geçmişindeki anahtarlar git-filter-repo ile temizlenmeli ve Google Play App Signing üzerinden anahtar rotasyonu talep edilmelidir.

Bulgu 2: Android Manifest Üzerinde allowBackup ve usesCleartextTraffic İzinleri
ORTA / DOĞRULANDI

CWE Sınıflandırması: CWE-276 (Incorrect Default Permissions), CWE-319 (Cleartext Transmission)

Etkilenen Dosya: android/app/src/main/AndroidManifest.xml (Satır 5, 11)

<application android:allowBackup="true" android:usesCleartextTraffic="true" ...>

Olası Etki: allowBackup="true", fiziksel erişim durumunda USB hata ayıklama (ADB) üzerinden uygulamanın tüm yerel depolama verilerinin (görevler, finans, notlar) kilitli ekrandan dahi bilgisayara kopyalanabilmesine imkan tanır. usesCleartextTraffic="true" ise şifresiz HTTP trafiğine izin vererek MitM saldırılarına zemin hazırlar.

Önerilen Düzeltme: Her iki parametre de false olarak ayarlanmalı veya şifresiz trafik izni kaldırılmalıdır.

Bulgu 3: Capacitor WebView Karma İçerik (allowMixedContent) İzni
ORTA / DOĞRULANDI

CWE Sınıflandırması: CWE-311 (Missing Encryption of Sensitive Data)

Etkilenen Dosya: capacitor.config.json (Satır 8-10)

"android": { "allowMixedContent": true }

Olası Etki: Güvenli HTTPS oturumu içerisinde güvenli olmayan HTTP kaynaklarının yüklenmesine müsaade eder.

Önerilen Düzeltme: "allowMixedContent": false olarak değiştirilmeli ya da blok konfigürasyondan çıkarılmalıdır.

Bulgu 4: Firebase Hosting Üzerinde Eksik Güvenlik Başlıkları ve CSP Yokluğu
ORTA / DOĞRULANDI

CWE Sınıflandırması: CWE-1021 (Clickjacking), CWE-693 (Protection Mechanism Failure)

Etkilenen Dosyalar: firebase.json, index.html

Açıklama: firebase.json yapılandırmasında HTTP güvenlik başlıkları (X-Frame-Options, X-Content-Type-Options, Referrer-Policy) ve Content Security Policy (CSP) tanımlanmamıştır.

Önerilen Düzeltme: Firebase Hosting yapılandırmasına headers bloğu eklenerek Clickjacking ve MIME-sniffing korumaları etkinleştirilmelidir.

Bulgu 5 & 6: ProGuard/R8 Karartma ve Tarih Formatlarında Savunma Derinliği
DÜŞÜK / İNCELEME GEREKLİ

CWE Sınıflandırması: CWE-656 (Reliance on Security Through Obscurity), CWE-79 (Improper Neutralization)

Etkilenen Dosyalar: android/app/build.gradle (Satır 30: minifyEnabled false), script.js (Satır 254, 1269)

Açıklama: Release derlemesinde kod küçültme/karartma kapalıdır. Ayrıca script.js içerisindeki task.createdAt ve formatExpenseDate metinleri doğrudan HTML şablonuna basılmaktadır; normal kullanımda güvenli format döndürse de, savunma derinliği (defense-in-depth) açısından escapeHtml() ile sarılması önerilir.

Bulgu 7: "Çok Kullanıcılı Yetkisiz Erişim / IDOR / Oturum İhlali" İddiası
YANLIŞ ALARM (FALSE POSITIVE)

Açıklama: Uygulama merkezi bir sunucuya veya kullanıcı hesapları veritabanına sahip değildir. Tüm veriler yalnızca yerel cihazda depolanmaktadır. Playwright çoklu oturum testinde de kanıtlandığı üzere, kullanıcılar arası veri sızıntısı veya IDOR riski mimari gereği imkansızdır.

5. Mobil Cihaz / Emülatör Durumu Beyanı

Geliştirme ortamına bağlı fiziksel bir Android cihaz veya aktif emülatör bulunmadığından, "APK cihaz üzerinde çalıştırıldı" şeklinde gerçeğe aykırı bir bildirim yapılmamıştır. Mobil değerlendirme; kaynak kodları, Gradle konfigürasyonu, Android Manifest izinleri ve Capacitor köprüsünün statik/mimari denetimiyle gerçekleştirilmiştir.

6. Önceliklendirilmiş İyileştirme Yol Haritası

Öncelik Aksiyon Konusu Risk Derecesi Tavsiye Edilen Aksiyon
